# NexaBox 2.0 — النسخة المحسّنة

هذه الحزمة إعادة تطوير فعلية لواجهة NexaBox ووظائف الدخول والمزامنة، وليست مجرد تغيير اسم للنسخة السابقة.

## ما تم تطويره
- إعادة تصميم الواجهة الرئيسية وبطاقات المشاريع وشاشة الحساب والإعدادات لتكون أكثر وضوحاً واستجابة للهاتف واللوحي.
- تحسين إنشاء الحساب وتسجيل الدخول والتحقق من البريد، مع رسائل أخطاء داخل الشاشة بدلاً من الاعتماد على التنبيهات فقط.
- إضافة إظهار/إخفاء كلمة المرور وطلب رابط إعادة تعيين كلمة المرور.
- تحسين تهيئة Supabase والتحقق من صيغة رابط المشروع والمفتاح العام قبل حفظ الإعدادات.
- جعل استعلامات المشاريع مرتبطة صراحةً بمعرّف المستخدم، مع جلب ومقارنة التعديلات قبل الرفع لتقليل الكتابة فوق البيانات الأحدث.
- تحسين رفع ملفات ZIP وAPK واستعادتها من مخزن خاص، وإضافة حالات أوضح للمزامنة.
- تقوية سياسات RLS وسياسات Storage بحيث لا يستطيع المستخدم الوصول إلا إلى مشاريعه وملفاته.
- تحديث Service Worker لمنع اعتراض طلبات Supabase الخارجية وإرجاع صفحة HTML بدلاً من استجابة API عند انقطاع الشبكة.
- تحديث التخزين المؤقت إلى إصدار جديد لإجبار الأجهزة على تحميل ملفات الواجهة الجديدة.

## التشغيل وربط الحساب والسحابة
1. فك ضغط الحزمة وارفع **محتوياتها** إلى استضافة HTTPS مثل GitHub Pages. لا ترفع ملف ZIP نفسه باعتباره الموقع.
2. افتح مشروع Supabase الخاص بك، ثم SQL Editor.
3. نفّذ الملف `supabase/schema.sql` مرة واحدة.
4. من NexaBox اضغط «ربط Supabase»، وأدخل Project URL والمفتاح العام `anon` أو `publishable` فقط.
5. أنشئ حساباً ببريد صالح وكلمة مرور لا تقل عن 8 أحرف. إذا كان تأكيد البريد مفعلاً، افتح رسالة التأكيد أولاً ثم سجّل الدخول.
6. اضغط «مزامنة الآن». كرر إعداد رابط المشروع والمفتاح على أجهزتك الأخرى ثم سجّل الدخول بالحساب نفسه.

## متطلبات وحدود مهمة
- لا يمكن إكمال اختبار إنشاء الحساب أو نقل ملفات السحابة من دون مشروع Supabase فعلي وبياناته العامة؛ هذه الحزمة لا تتضمن حساباً أو مفاتيح تخص المستخدم.
- لا تضع `service_role` أو أي مفتاح سري في ملفات HTML أو JavaScript.
- يجب أن تكون Redirect URLs في Supabase Auth متوافقة مع عنوان الموقع المنشور حتى تعمل روابط تأكيد البريد واستعادة كلمة المرور.
- حد حجم الملف في إعداد bucket هنا 500MB، لكن حد المشروع وخطة Supabase قد يكونان أقل. راجع حد التخزين في لوحة Supabase.
- التخزين المحلي في IndexedDB مرتبط بالمتصفح والجهاز. استخدم النسخ الاحتياطي المحلي قبل حذف بيانات المتصفح أو تغيير الجهاز.
- هذه نسخة Web/PWA وليست APK أندرويد. يمكن تغليفها لاحقاً في WebView بعد اختبارها على رابط HTTPS.

## ملفات مهمة
- `index.html`: التطبيق والواجهة والمنطق البرمجي.
- `supabase/schema.sql`: الجداول وسياسات حماية الحسابات والملفات.
- `sw.js`: التخزين المؤقت والعمل الأساسي دون اتصال.
- `CHANGELOG_AR.md`: ملخص التغييرات.
