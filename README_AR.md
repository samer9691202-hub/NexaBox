# NexaBox — إصدار محسّن

مستودع لإدارة مشاريعك وملفات ZIP وAPK، مع تخزين محلي ونسخ سحابي عبر Supabase.

## ما تم تحسينه
- تحديث الواجهة لتكون أوضح ومتجاوبة مع الهاتف والكمبيوتر، مع تحسين البطاقات والأزرار والنوافذ.
- تحسين إنشاء الحساب وتسجيل الدخول: التحقق من البريد وكلمة المرور (8 أحرف على الأقل)، ومعالجة أخطاء Supabase، ورسالة واضحة عند تفعيل تأكيد البريد.
- تعديل ترتيب المزامنة: جلب بيانات السحابة أولاً ثم مقارنة وقت التحديث قبل رفع النسخ المحلية، بدلاً من رفع كل شيء عشوائياً.
- منع إعادة رفع ملفات ZIP وAPK في كل مزامنة، وحفظ مسار الملف السحابي بعد رفعه.
- تحديث مسار الملف عند استبدال ZIP أو APK محلياً.
- تحسين استرجاع ملفات التخزين السحابي، وإظهار حالة المزامنة.
- تحديث Service Worker وإزالة ملفات التخزين المؤقت القديمة، مع استخدام الشبكة أولاً لصفحة التطبيق.
- الحفاظ على العمل المحلي والنسخ الاحتياطي JSON.

## تشغيل وربط الحساب والسحابة

### 1) إعداد Supabase
1. أنشئ مشروعاً في Supabase.
2. افتح SQL Editor والصق محتوى `supabase/schema.sql` كاملاً ثم نفّذه.
3. من Authentication → URL Configuration أضف عنوان موقعك إلى Site URL و Redirect URLs.
4. من Authentication → Providers تأكد من تفعيل Email.
5. إذا كان تأكيد البريد مفعّلاً، افتح رسالة التأكيد قبل تسجيل الدخول. يمكنك تعطيله من إعدادات Auth أثناء الاختبار فقط إذا كان ذلك مناسباً لك.

### 2) ربط التطبيق
1. افتح NexaBox ثم اختر «ربط Supabase».
2. أدخل Project URL من إعدادات المشروع، ثم المفتاح العام Publishable أو anon.
3. لا تضع `service_role` داخل التطبيق أو ملفات الموقع مطلقاً.
4. احفظ الاتصال ثم أنشئ حساباً أو سجّل الدخول.

### 3) استخدام أكثر من جهاز
- انشر ملفات الموقع نفسها على استضافة HTTPS.
- افتح NexaBox على الجهاز الثاني، وأدخل رابط Supabase والمفتاح العام نفسيهما.
- سجّل الدخول بالحساب نفسه، ثم اضغط «مزامنة الآن».
- بيانات المشاريع محفوظة في جدول `projects`، والملفات في bucket خاص باسم `nexabox-files`. سيحمي Row Level Security بيانات كل مستخدم من حسابات المستخدمين الآخرين.

## ملاحظات مهمة
- النسخة الحالية لا تحتوي على بيانات اعتماد Supabase الخاصة بك؛ لذلك لا يمكن اختبار حساب حقيقي أو إتمام الربط السحابي قبل إدخال Project URL والمفتاح العام وتنفيذ SQL.
- لا تشارك كلمة مرور حسابك أو مفتاح `service_role` مع أي شخص.
- المزامنة ليست نظاماً تعاونياً متعدد المستخدمين؛ كل مستخدم يرى مشاريعه فقط.
- إذا عدّل الجهازان المشروع نفسه في الوقت ذاته، تعتمد المزامنة على وقت آخر تحديث. احتفظ بنسخة JSON دورية للملفات المهمة.
- ملفات APK قد تكون كبيرة؛ تأكد من حدود التخزين والرفع في خطة Supabase لديك.
- افتح الموقع عبر HTTPS أو localhost حتى تعمل ميزات PWA والتخزين المحلي بصورة صحيحة.
